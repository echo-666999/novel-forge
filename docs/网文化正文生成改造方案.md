# 网文化正文生成改造方案：去 AI 味、多线叙事、文风可选

> 编写日期：2026-11-27
> 范围：设定、大纲、细纲、正文、检查、评审各阶段的提示词与契约，建书向导，评审门禁，人工修正入口
> 状态：方案稿，未改代码。第八节的决策事项已于 2026-11-27 由作者答复，答复记录在 8.3；验证书创意待作者确认（4.8）
> 诊断样本：小说 #22《铜钥匙（提示词A对照）》已正式提交的第 1–50 章，共 145,156 字

---

## 一、结论先行

1. **问题主要出在上游，正文这一层只占小部分。** 第 22 本书的正文逐句看并不差：现有可读性指标显示对白占比 21.9%，流程词每千字 4.6 个，都在门禁范围内。读起来像"警察办案记录"，根源有四个：
   - 原始创意本身要求"节奏克制、慢节奏、只能靠档案和物证推进"；
   - 设定决策把"合规移交程序"写成了结局路径；
   - 全书路线把唯一的宏观目标（打开第三格卷柜）拖到第 85 章才兑现；
   - 系统里没有任何一环衡量"好不好看"。
2. **系统目前只为"正确"做了优化，没有为"好看"做优化。** 推进点核验、待核台账、已揭示事实、实体审批、事件提取、评审，这些都在保证不出错。对"有没有情绪起伏、有没有爽点、人物是否鲜明、章节是否雷同"，没有一个检查点负责。
3. **系统自己的规则语言漏进了人物嘴里。** 正文生成时注入了"待核事项只能写成怀疑""推进点要有可核验证据""按合规程序"等约束，模型把它们直接变成了台词，例如"先写清来源""我得再核一遍"。用户摘出的 AI 腔句子，大多是这样来的。
4. **开头雷同有一个可以直接定位的机械原因。** 细纲 Schema 要求每个场景填写 `time` 字段（例如第 45 章细纲第一场是"次日上午九点多 / 区档案馆修复室"），正文就把它写成了开头的第一句。50 章里有 33 章用时间短语开头。
5. **改造方向：好看优先，正确兜底。** 正确性机制保留，但改为分级：只有影响情节推进的硬伤才阻断，其余记为瑕疵，交给人工处理。腾出的请求预算转给文风和情绪。具体做法是引入"题材包 + 文风预设 + 人物声纹 + 多线编排 + 爽点节奏"五个新输入，以及一个"阅读体验评审"。

### 2.2 七个问题与成因

| # | 现象 | 直接成因（代码 / 数据位置） | 深层成因 |
|---|---|---|---|
| D1 | 每章开头高度相似 | 细纲 Schema 每场景必填 `time`、`place`（`ContentExecutionContract` 细纲 Schema）；场景固定 3–5 个；`StyleSignals` 只把近 3 章开头作为"提示"，不阻断 | 场景模板固定成"时间 + 地点 + 动作"，模型照字段顺序写 |
| D2 | AI 腔 | ① 高频小动作；② 系统规则漏进台词：`openItemInstructions`、推进点 `verification`、设定决策中的"合规"；③ 正文系统指令中约 80% 是格式、字数、连续性约束，写法指导只占一小段；④ 正文模型为 deepseek-flash，温度 0.7；⑤ 修订只针对"问题"做局部替换，会把有棱角的写法磨平 | 约束越多，模型越保守；保守写法正是 AI 味的来源 |
| D3 | 流程化、公式化 | 原始创意与 `creative_brief` 都写了"克制、慢节奏、每个发现都来自修复工作"；设定 `tone.narrative_style` 为"以修复工作的具体步骤带动调查发现"；第 4 条决策规定结局证据须"经合规移交程序……依法启封" | 每章 1–3 个"可核验推进点"在宏观目标被拖延时，只能退化成"每章多拿到一条小线索"。路线图 6 个转折点均匀铺在 100 章里，中间缺少阶段性兑现 |
| D4 | 人物扁平 | 设定提示词"生成一至三张主要人物卡"；人物卡只有 name / role / goal / personality / speech_style / abilities / limitations；配角没有任何卡片 | 人物卡里没有欲望、恐惧、秘密、缺点、口头禅、与主角的利害关系，也没有声音样本；人物于是只能靠"压低声音""往门外看"来区分 |
| D5 | 一镜到底 | `tone.pov` 为"第三人称限知，主要跟随沈禾"；大纲 Schema 没有"线索 / 视角"字段 | 没有可切换的第二视角，也没有并行的支线；每章只能是主角一个人"去问 → 对方犹豫 → 给半句 → 回家" |
| D6 | 没有爽点 | 大纲章节只有 title / summary / objective / conflict / hook / progression_points；评审维度是结构、截断、视角、时序、可读性、钩子、规则冲突 | 爽点、笑点、打脸、情绪峰值没有对应字段，也没有对应的检查，模型因此没有理由去写 |
| D7 | 逻辑抠得过严 | 推进点逐条证据、待核台账、已揭示事实回看、实体审批、事件提取、评审，层层门禁；评审"literary"意见全是挑错 | 所有资源都花在"不出错"上；作者要求"没有明显影响推进的逻辑问题即可"，现状远超这个要求 |
| D8 | 文风不可选 | 建书向导中"题材"是自由文本框，`creative_brief.style` 是一句自由文本 | 没有结构化的文风参数，模型只能从一句"克制、生活化"里猜 |

### 2.3 用户摘出的 AI 腔句子，逐句溯源

| 原句 | 来源 |
|---|---|
| "先写清来源。交不交、怎么交，得按程序来"（第 19 章） | 设定决策第 4 条"合规移交程序"，加上推进点要求"证据可核验" |
| "周叔说的就是这个位置。第三格放底册和签收。"（第 20 章） | 已揭示事实台账要求"只能承接，不能重新发现"，人物于是复述已知事实来"承接" |
| "先别问。我得再核一遍，核完跟您说。"（第 20 章） | 待核事项规则"只能写成待核、怀疑或推测"被人物说出口 |
| "我不调卷宗，只看一页签收栏。" | 人物卡 limitations 写着"没有执法权，无法调取封存档案"，模型让人物反复声明自己没越权 |
| "说清单得经手人签，别人递过去不算" | 场景自检规则"签字、登记、审批写过一次就算完成"被模型当成剧情素材 |

**结论**：要去掉这类句子，靠禁用词表只能治标。需要把系统约束改写成"给作者的写作要求"，并明确禁止人物把这些要求当台词念出来（见 4.5.3）。

## 三、设计原则

1. **好看优先，正确兜底。** 正确性机制分三级（4.7）：硬伤阻断，瑕疵记录，细节忽略。
2. **结构化输入代替一句话提示。** 文风、题材、人物、线索、爽点都变成有字段的数据，冻结进运行快照，沿用本项目"新协议版本 + 旧运行只读"的惯例。
3. **能由程序判定的交给程序。** 开头雷同、线索断档、爽点间隔、钩子类型重复、AI 腔词频，都能本地计算，不额外花请求。
4. **模型只判断程序判断不了的东西**，例如情绪是否到位、笑点好不好笑，并且起步阶段只作参考，不作门禁。
5. **作者始终有最终决定权。** 每一类自动判定都要有"作者接受 / 忽略 / 勘误"的入口。
6. **参考作品只学技法，不学内容。** 不复用书名、人物、桥段，也不把原文作为样例输入模型。

## 四、改造方案

### 4.1 题材包与文风预设（对应目标 5、8）

#### 4.1.1 题材包（Genre Pack）

"题材"从自由文本改为**下拉选择 + 自定义**。每个题材包是一组可编辑的结构化参数，冻结进设定、大纲、正文的输入。

| 字段 | 含义 | 示例（年代重生） |
|---|---|---|
| `key` / `name` | 标识 / 名称 | `era_rebirth` / 年代·重生 |
| `core_promise` | 给读者的核心承诺 | 前世吃过的亏这辈子一个个讨回来，日子越过越红火 |
| `payoff_types` | 本题材常用爽点类型及权重 | 打脸极品亲戚 30%、赚钱致富 25%、护短 15%、甜 15%、身份或眼界碾压 15% |
| `beat_template` | 卷级节拍 | 受压 → 反击小胜 → 更大的麻烦 → 借势翻盘 → 新台阶 |
| `world_rules_hints` | 世界观要点 | 年代物价、票证、政策节点要大致合理，不必精确到月 |
| `archetypes` | 常见人物原型 | 极品亲戚、刀子嘴豆腐心的长辈、闷声干大事的男主、嫉妒的同龄人 |
| `taboos` | 本题材禁忌 | 主角圣母、受辱后长期不反击、金手指无代价 |
| `default_style` | 推荐文风预设 | 生活口语 + 泼辣幽默 |

首批内置题材包（按作者要求，避开"现实生活""现实悬疑"）：**年代、重生、穿越、历史、架空、玄幻**，另提供"自定义"。

#### 4.1.2 文风预设（Style Preset）

管理页面新增"文风预设"列表，建书时选择一项，可以在本书内覆盖部分参数。

| 字段 | 含义 |
|---|---|
| `name` / `description` | 如"幽默风趣""严谨冷峻""生活口语""热血燃""轻松甜宠""古风雅致" |
| `narrator_attitude` | 叙述者口吻：吐槽、旁观、冷峻、温情、说书人 |
| `sentence_rhythm` | 长短句倾向、段落长度区间 |
| `dialogue_share` | 对白占比目标区间（例如口语风 35%–55%） |
| `humor_level` / `humor_devices` | 无 / 低 / 中 / 高；手法：反差、吐槽、误会、夸张、冷幽默、方言俏皮话 |
| `emotion_expression` | 外放 / 克制 / 先抑后扬 |
| `vocabulary` | 偏好词域（市井口语、方言、古风、网络梗等）及本预设禁用词 |
| `samples` | 2–3 段**原创**示范段落：由模型按本预设生成初稿，作者可在后台逐段修改、替换或删除；修改后生成新版本 |
| `draft_fragment` | 注入正文系统指令的写法要求（由上面各字段渲染，可手改） |

**题材包和文风预设都是可增删的列表**：后台可以新建、复制、修改、停用，内置项也可以停用。已停用的项不出现在建书下拉框里，但已冻结使用它的书不受影响。首批内置项只是初始数据。

存储建议：新建版本化的 `style_presets` 表，或复用现有 `prompt_template_versions` 的"草稿 → 测试 → 发布 → 回滚"机制，增加一类 scope。建书时把选中版本整体冻结进 `generation_config`，已有运行不受后续修改影响，这与现有提示词模板的冻结方式一致。

#### 4.1.3 文风示例：同一个情节，三种写法（方案示意，非最终提示词）

情节：女主去讨要被亲戚扣下的钱。

- **生活口语 · 泼辣**："三婶，这钱您揣兜里一年了，兜不嫌沉，我都替它嫌闷。"她往门框上一靠，瓜子壳吐得又准又脆。
- **幽默风趣**：三婶的脸色从红到白，又从白到青，跟村口刚换的红绿灯似的。偏偏这灯坏了，卡在黄灯上半天不动。
- **严谨冷峻**：她没进门。账本摊在门槛上，一页一页翻过去，翻到第三页时，三婶的手已经开始抖了。

### 4.2 人物系统（对应目标 3）

#### 4.2.1 人物卡扩展（设定 Schema v2）

| 新增字段 | 用途 |
|---|---|
| `desire` | 想要什么（具体、可失去） |
| `fear` | 最怕什么 |
| `secret` | 别人不知道的事（作者可见，角色可不知） |
| `flaw` | 会让他吃亏的毛病 |
| `quirks` | 1–3 个辨识度细节（口头禅、习惯动作、穿着） |
| `voice_samples` | 2–3 句有代表性的台词 |
| `relation_to_protagonist` | 与主角的利害关系，以及这种关系怎么变 |
| `arc` | 起点 → 终点 |
| `tier` | 主角 / 核心配角 / 功能配角 |

规则：
- 人物卡从 1–3 张放宽到**主角 1 + 核心配角 3–6 + 反派 1–2**。
- **任何在正文中出现三次以上的人物，必须有名字和至少一张简卡**（功能配角只需 name / quirks / voice_samples / desire）。由事件提取阶段统计出现次数，达到阈值后提示作者补卡，或由模型补卡后交作者批准，复用现有实体审批流程。像"主管"出现 149 次仍无名字的情况会被拦下。

#### 4.2.2 声纹注入

正文请求里只注入**本章出场人物**的 `quirks`、`voice_samples`、`speech_style`、`desire`，并附一条要求："不同人物说话要能分辨，遮住名字也能认出谁在说话。"

#### 4.2.3 情绪调色

细纲场景字段 `emotional_beat` 改为结构化的 `{人物, 情绪, 触发, 外在表现}`。另加本地检查：一章内情绪种类少于 2 种、连续 5 章都没有出现"喜 / 怒 / 哀 / 惧 / 惊"中的外放情绪时，记为瑕疵，下一章大纲请求附带提醒。

### 4.3 多线叙事（对应目标 4）

#### 4.3.1 线索定义（大纲 Schema v2，首批的 roadmap 增加 `threads`）

```text
threads: [
  { key: "A", name: "主线：讨回家产", type: "main",         owner: "女主",   goal: "...", stakes: "..." },
  { key: "B", name: "事业线：摆摊到开店", type: "sub",      owner: "女主",   goal: "..." },
  { key: "C", name: "反派线：堂姐的算计", type: "antagonist", owner: "堂姐", goal: "..." },
  { key: "D", name: "感情线 / 家庭线",   type: "relationship", owner: "...", goal: "..." }
]
```

#### 4.3.2 章节字段

每章新增：
- `focus_threads`：1–2 条，第一条为主；
- `pov`：本章主视角人物，允许非主角；
- `cutaways`：可选，0–2 个短切镜头，用于反派线或远处进展，每个 200–600 字。

#### 4.3.3 编排规则（由程序本地校验，不花请求）

| 规则 | 建议值 |
|---|---|
| 主线连续独占的章数上限 | 4 章 |
| 任一支线断档的章数上限 | 8 章（可按线索设置） |
| 非主角视角章节占比 | 10%–30%（题材包可调） |
| 同一组"开场地点 + 收尾人物"连续出现的上限 | 2 章 |

不满足的批次退回重生成一次，带上具体违规；仍不满足就交作者处理，沿用现有大纲的"一次恢复"上限，不会无限循环。

#### 4.3.4 与现有卷弧规划衔接

`StoryStructure` 已经支持卷和弧，以及各自的 goal / turning_point / climax / ending_state。建议在弧上增加 `threads_in_play`，让"本弧哪几条线在走"由作者可视化编辑。

### 4.4 节奏与爽点（对应目标 6）

#### 4.4.1 爽点分类（题材包可增删）

打脸、逆袭、揭秘、获得（钱 / 物 / 能力 / 盟友）、身份揭露、智斗胜出、护短、甜、笑点、危机解除。

#### 4.4.2 大纲章节新增字段

| 字段 | 内容 |
|---|---|
| `payoff` | `{type, setup_chapter, description}`；允许 `type = none`，但有比例限制 |
| `emotional_peak` | 本章情绪最高点（谁、什么情绪、为什么） |
| `hook_type` | 悬念 / 危机 / 反转 / 情感 / 期待 |

#### 4.4.3 节奏规则（程序校验）

- 每章至少有一个**小兑现**（小爽点、笑点或情绪峰值，三者之一）；
- 每 3–5 章有一个**中兑现**，即一次完整的"压 → 扬"；
- 每弧（建议 10–25 章）以一个**大兑现**收尾，**宏观目标必须在弧内达成或明确改变**。像第 22 本书这样一个目标拖 85 章的路线图，在冻结前就会被拦下；
- `hook_type` 不得连续 3 章相同；
- 铺垫到兑现的间隔超过题材包设定（例如 15 章）时，提醒作者。

#### 4.4.4 推进点的口径调整

推进点保留（它是 PRD 防止"原地打转"的硬约束），调整两处：
- `verification` 从"正文中可检查的完成证据"改为"读者能感受到的变化"，检查阶段允许以人物反应和后果作为证据，不要求出现可引用的"那一句"；
- `change_type` 增加 `payoff`（兑现）和 `emotion`（情绪立场），让"爽到了""和好了"本身也算推进。

### 4.5 去 AI 味（对应目标 1、2）

分五层，从便宜到贵。

#### 4.5.1 去掉机械成因（P0，改提示词和 Schema 即可）

1. 细纲的 `time` 改为可选的 `time_shift`，只在时间跳转时填写。正文指令写明："不要用时间或天气作为章节第一句。"
2. 新增 `opening_mode`（对白开场、动作中途、冲突进行时、悬念抛出、反常细节、人物内心），由程序**轮换指定**：本章不得与前两章相同。
3. `StyleSignals` 的开头 / 结尾雷同从"提示"升级为**质量问题**，走现有的单场景 quality 修复通道。修复范围只限第一段或最后一段，成本很低。
4. 场景数量从固定 3–5 个，改为**按情节需要 2–5 个**，允许"一场大戏写满一章"。

#### 4.5.2 AI 腔词表（P0）

- 建立**全局 AI 腔表**（初稿见附录 A），加上**文风预设自己的禁用词**。
- 本地统计每千字频次和跨章频次：超过阈值时，正文请求里附"本章避开下列表达"，超过上限的走 quality 修复。阈值先按第 22 本书的分布定，例如"指腹"每章最多 1 次。
- 注意：只禁词会催生新的替代套话，所以词表要定期从近 10 章里自动更新（现有 `StyleSignals::phrases` 已具备这个能力，把它的结果并入词表即可）。

#### 4.5.3 规则语言防火墙（P0，收益最大）

1. 所有注入正文的约束（待核事项、已揭示事实、推进点、场景自检）统一加一句："以上是给作者的写作约束，**人物不知道这些规则**。不要让人物在台词或内心中说出'核对、来源、程序、签收、登记、待核'之类的话，除非情节本身需要。"
2. 检查阶段新增**台词流程词**的本地统计：引号内流程词每章超过 N 次即记为瑕疵，并给出改写建议。
3. 设定决策提示词增加一条："决定剧情时，优先选择有冲突、有代价的方案，不要以'合规程序'作为解决手段。"同时题材包的 `taboos` 写明"不以走流程推动情节"。

#### 4.5.4 正文提示词重排（P1）

现状：系统指令前面是格式、字数、槽位、连续性，写法只占一段。

建议改为：
- **系统指令** = 文风预设渲染出的"写法要求"，加上 1–2 段原创示范，加上本章的情绪和爽点目标；
- **输出契约** = 格式、字数、槽位规则，放在后面，保持现有内容不变。

这样做不会削弱现有约束，只是改变模型的注意力重心。

#### 4.5.5 模型与风格化润色（P1–P2，需要 A/B 实测）

1. **按步骤选模型**（作者已同意，不设单章成本上限，但要能省则省）：当前 `generation_config` 只有一个 `model`，需要新增按步骤的模型映射，这是新能力。省钱策略：
   - 只有**正文首稿**和**场景重写**用写作能力强的模型（配置中已有 Claude Sonnet 5.5 / Opus 5.5 / Fable 5.2）；细纲、提取、检查、评审、字数修复继续用 deepseek-flash；
   - 强模型的请求复用现有"共享资料前置"布局（`ContextBuilder` 的 shared-first），让同一章各步骤命中提示词缓存；
   - 降低严格度后，修订和修复次数减少，省下的请求抵消一部分强模型的成本；
   - 每本书在概览页显示"正文步骤 / 其他步骤"的分项费用，方便作者判断值不值。
2. **风格化润色（可选）**：通过检查后增加一次整章文风润色，"只改表达，不改事实"。事实是否被改，复用现有正式稿修订的事实等价核对（`FormalRevisionService` 的 equivalence 流程）。这一步每章多 1–2 次请求，建议作为每本书的开关，默认关闭，先做 A/B。

### 4.6 评审改造：新增"阅读体验"维度（对应目标 1、2、6）

现有评审只判断"对不对"。新增 `reading_quality` 评审，可与现有评审合并为一次请求，输出：

| 维度 | 1–5 分 | 说明 |
|---|---|---|
| 爽感 / 兑现 | | 本章计划的 payoff 是否写出了"爽"，而不只是"提到了" |
| 情绪 | | 有没有让读者跟着急、气、笑、心疼的地方 |
| 人物辨识度 | | 遮住名字能否分辨说话人 |
| 节奏 | | 有没有拖沓、反复交代、原地踏步 |
| 文风贴合 | | 与所选文风预设是否一致 |
| AI 腔 | | 套话、空泛比喻、程式化小动作 |
| 一句话最该改的地方 | 文本 | 给作者看 |

上线分两步：
1. **前 2–3 本书只记录不阻断**，作者同时给每章打分，用来校准模型评分；
2. 校准后，再对"爽感 ≤ 2 且情绪 ≤ 2"这类组合启用一次自动重写。

现有评审中的 `literary` 意见降级为不阻断的"文字瑕疵"，不再触发修订。

### 4.7 逻辑分级与人工修正入口（对应目标 7）

#### 4.7.1 三级口径

| 级别 | 处理 | 例子 |
|---|---|---|
| **硬伤**（阻断提交） | 自动修复一次，失败交作者 | 已死人物开口；关键物件无故易手并影响后续情节；时间线倒错导致因果颠倒；违反作者确认的世界规则；正文截断、格式错误、视角人称错乱（如第 50 章开头"让我明天再来"的人称跳变） |
| **瑕疵**（记录不阻断） | 进入"问题清单"，作者可接受、忽略或勘误 | 小动作前后不一致；称谓偶尔不统一；同一信息重复交代；配角出行方式没有交代 |
| **忽略** | 不检查 | 修辞、笔的种类这类物理细节；合理的回忆与重述 |

#### 4.7.2 每本书增加"严格度"设置

宽松（网文默认）/ 标准 / 严格（悬疑推理）。严格度决定：
- 待核台账、已揭示事实回看、推进点逐条证据这三项是**阻断**还是**提示**；
- 检查阶段 `continuity_issues` 哪些类别升级为阻断；
- 新实体是否自动采纳。网文默认自动采纳，作者事后在实体库修改。

4. 降级的问题仍保存在评审记录里，章节页标为"瑕疵（按本书严格度只记录）"，作者可以事后手改。
5. 入口：建书向导"生产方式"一步选择；已有的书在小说页"评审严格度"按钮修改。验证书第 23、24 本已改为宽松，其余已有的书保持严格。

- **后续章纲感知偏差**：下一章细纲发现上一章交接里有章纲外的约定时，在本章开头用一个短场景交代结果（去了 / 推迟 / 没去及原因），不必重排大纲。

**R4 设定矛盾与主线目标阶梯（解决第 4 条）**

- 设定阶段新增"主角当前处境"（身份、工作、住处、日常时间安排）和"主线目标阶梯"（先做成什么、再做成什么，各自的取舍），从创意中推出。

**R5 伏笔账本自动登记（解决第 7 条）**

**R6 不选预设时的默认文风（解决第 1 条遗留）**

## 八、做不到、不确定、需要作者拍板的地方

### 8.1 做不到或无法保证的

1. **"读不出是 AI 写的"无法客观证明，也无法保证。** 本方案能消除可识别的套路（开头、小动作、台词念规则、情绪单一），能否让读者完全读不出来，取决于模型能力和作者把关，只能用盲读来检验。
2. **文笔上限受模型制约。** deepseek-flash 在当前约束下能写到什么程度，本次没有实测。改造后可能仍需要更强的模型来写正文，成本会上升，具体多少要等 A/B 结果。
3. **幽默是模型最容易写尬的部分。** 文风预设里的示范段落质量决定上限，建议由作者亲自写或挑选 2–3 段；笑点是否成立，最终只能靠作者判断。
4. **参考作品的原文不能作为样例输入模型**（版权问题，也会导致模仿过度）。只能抽象技法。我也没有通读这三部作品，第 4.8 节的归纳精度有限。
5. **第 22 本书已生成的 50 章，改不了结构性问题。** 正式稿修订只能"改表达、不改事实"，能去掉部分 AI 腔，但单线、慢节奏、主线停滞是剧情层面的问题，只有重新规划或另起新书才能解决。

### 8.2 不确定、需要在实施前核实的

1. 多视角（非主角 POV）章节与现有角色知识（`CharacterKnowledge`）、事件提取协议是否兼容，没有验证。
2. "从第 N 章起重写"能否直接复用现有候选基线机制，需要读完 `CanonicalBaselines` / `AcceptanceBranch` 后再判断。
3. 第六节的阈值（AI 腔词频、线索断档章数、爽点间隔）是根据第 22 本书和题材常识定的初值，需要用验证书校准。
4. 压缩核验层后，PRD 中"情节原地打转"的老问题是否会复发，需要观察。本方案保留推进点和执行次数上限，理论上不会，但没有实测。
