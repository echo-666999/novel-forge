# 后台界面优化方案：简洁、紧凑、重点突出

> 编写日期：2026-11-14
> 范围：`app/Filament` 下全部后台页面及对应 Blade 视图
> 状态：四个阶段均已完成（2026-11-14）

## 一、目标与原则

后台主要用来维护小说内容，即设定、大纲、正文、阅读和提交。请求、费用、尝试等过程记录只在排查问题时才需要看。按以下四条原则调整：

1. **第一屏只放“现在是什么状态、下一步做什么”**：状态用标签，下一步用一个主按钮表示。
2. **过程记录一律默认收起**：请求次数、请求上限、尝试历史、费用、Token、调用编号、记录编号、原始错误码、冻结 JSON 都属于过程记录，统一放进页面底部默认收起的区块，或放进弹窗。
3. **异常不靠展开区块提醒**：需要提醒时（金额未知、预算将尽、额度用尽），在页面顶部显示一个警示标签或一行提示，并附上入口链接。
4. **说明文字不占正文位置**：大段说明放进标题旁的「?」提示里，确认类说明只在确认弹窗中出现。

## 二、已完成的页面（作为参考样式）

以下页面已按上面的原则改过，后续页面沿用同样的做法：

| 页面 | 采用的做法 |
|---|---|
| 小说书架 `/admin/novels` | 合并列、执行次数列默认隐藏、次要操作收进“⋯”菜单 |
| 小说概览 `/novels/{id}` | 顶部状态标签行、近期章节表、设定字段紧凑网格 |
| 章节目录 `/chapters` | 只保留章节、状态、字数、更新时间四列 |
| 正文工作台 `/content` | 检查、评审、提取、提交都改成卡片，证据用“第N段：原文”列出 |
| 阅读器 `/reader` | 标签式头部、首行缩进段落、操作收进两个分组 |
| 角色知识、故事状态、实体库 | 顶部概览标签、卡片网格 |
| Prompt 模板管理 | 生效概览卡片、每行一个主操作、旧版本默认收起、编辑页实时预览 |

**通用组件约定**（已在上述页面使用）：
- 顶部概览用 `Flex` 加若干 `badge` 形式的 `TextEntry`，配色固定：绿色表示完成或生效，蓝色表示进行中，橙色表示待处理，红色表示失败，灰色表示附属信息。
- 列表优先用卡片网格，表格只保留 4～5 列。
- 时间统一用 `since()` 显示，悬停时显示完整时间。

## 三、全局规则：请求记录统一收起

### 3.1 需要收起的信息
| 类别 | 例子 |
|---|---|
| 请求计数 | 已用 / 授权请求、已领用 / 请求上限、提交准备请求 x / 2、本轮质量修复合计请求、本次运行真实 AI 请求 |
| 执行额度 | 执行次数 / 上限、尝试总数、阶段尝试次数 |
| 费用 | 实际费用、估算费用、全部调用汇总、费用日志编号 |
| 技术标识 | 运行编号、阶段编号、调用日志编号、记录 #、清单编号、供应商请求编号、原始错误码 |
| 冻结参数 | 冻结模型、输出 Token 上限、冻结段落预算、完整 Prompt、授权 JSON |

### 3.2 统一的收起方式
- 每个页面最多保留**一个**“运行记录”区块，标题固定为「请求与费用记录」，放在页面最底部，`collapsible()->collapsed()->compact()`。
- 区块标题的描述只写一行摘要，例如“12 次请求 · ¥3.20 · 1 次金额未知”。不展开就能知道大概情况，但不占正文位置。
- 原来散落在多个区块里的请求和费用字段都并入这个区块。
- 编号类字段一律不单独占一列或一个字段，改成灰色小字附在条目末尾，例如“#123”，或者放进详情弹窗。

### 3.3 取消“自动展开”
- 目前小说概览的「预算、费用与执行次数」会在预算接近或已经用尽时自动展开。改为**始终收起**；预算告警改由顶部状态标签行中已有的预算标签显示红色或橙色。
- 有金额未知的请求时，在顶部显示一个橙色标签“1 次请求金额未知”，点击跳到「费用明细」，并带上“计费状态 = 未知”的筛选条件。

## 四、逐页方案

优先级：**P1** 每天都会用、收益最大；**P2** 经常用；**P3** 偶尔用或属于诊断页。

### P1 小说概览 `ViewNovel` + `NovelInfolist`
- 「预算、费用与执行次数」：按 3.3 改为始终收起，并改名为「请求与费用记录」，移到页面最底部。
- 「设定执行记录」（尝试次数、请求模型、调用日志编号）并入同一个区块。
- 页头操作有 11 个，按状态显示。建议同一时刻最多露出 2 个主操作，例如“生成大纲”或“继续自动生成”；「调整预算」「接管本书」「刷新状态」「导出正式章节」收进“⋯”菜单。
- 确认弹窗中的长说明（例如“启用细纲时依次调用细纲、正文、独立推进检查……”）缩成一句结论，加一个“查看计费说明”的折叠段落。

### P1 正文工作台 `ViewChapterContent`「运行与历史」标签页
- 「章节运行」目前展开显示 12 个字段，其中 7 个是请求或冻结参数。拆成两部分：
  - **留在第一屏的 4 项**：运行状态、当前步骤、细纲来源、停止原因与下一步，用标签加一行文字显示。
  - **收进「请求与费用记录」的**：已领用 / 请求上限、提交准备请求、持续验收范围、本轮修复方式、本轮质量修复合计请求、冻结模型、输出 Token 上限、冻结段落预算。
- 「生成与恢复历史」和「尝试与费用」两个区块合并为一个「请求与费用记录」，里面用两个子标题区分，“查看完整 Prompt”按钮保留在区块头部。
- 历史运行列表改成卡片，每行显示“第 N 次运行 · 状态 · 停止原因”，编号和“领用 / 上限”改成灰色小字。

### P1 运行与恢复 `ViewNovelRun`
- 「当前运行」去掉“暂停请求：未请求”这个字段，只在已经请求暂停时显示一个橙色标签“已请求暂停”；“正式章数 / 故事版本”改成标签。
- 「自动生产运行与进度」：
  - 授权范围、当前章、当前步骤合成一行标签；停止原因和建议下一步合成一张红色提示卡，只在出错时显示。
  - “本书全部生产运行”表格（运行编号、原始错误码）移入「请求与费用记录」。
- 「请求与执行次数」「阶段流水线」「已有生成与提交产物」「运行控制记录」这 4 个收起区块，合并为一个「请求与费用记录」，里面用子标题区分；「技术详情」也并进去。整页的折叠区块从 6 个减少到 1 个。

### P1 生产总览 `ProductionOverview`
- 「生产与服务状态」里的“金额未知的真实请求”数字，改成只在数量大于 0 时显示一个橙色标签；Worker 心跳和检索覆盖改成一行状态标签，正常时显示绿色“服务正常”，异常时显示具体项。
- 「待我处理」和「正在运行」改成卡片列表：每项一张卡，显示小说名、事项和一个按钮，不再用 4 列表格。

### P2 大纲 `ViewOutlinePlan`
- 「大纲计划」去掉“确认设定记录编号”和“请求模型”；计划状态、已接纳 / 目标章数、下批起始章改成顶部标签行，停止原因只在有值时显示为提示卡。
- “全书走向”和“终局方向”保留在正文区域，是这一页的重点。
- 「批次尝试与费用」改名为「请求与费用记录」，阶段编号和调用日志编号改成灰色小字。

### P2 正式稿修订 `FormalRevisions`
- 顶部说明有 100 多字，压缩成一句“只改文字、事实不变：逐条取舍润色建议，改动后由模型核对事实”，其余内容放进「?」提示。
- “已用请求 x / y”移出标题行，放进「请求与费用记录」。
- 表格只保留章、状态、建议（合格 / 全部）、接受数四列；事实核对摘要和最近错误放进行详情。

### P2 章节运行中心 `GenerationRuns`
- 「运行编号」和「父运行」两列默认隐藏；创建时间改用 `since()`。
- 「下一步骤」显示中文步骤名，不显示内部键。
- 去掉内容为空、只有一段说明文字的区块，说明改为表格描述，或放进「?」提示。

### P3 费用明细 `ViewNovelCosts`（诊断页）
- 这一页本身就是请求记录，保留，但默认只显示 5 列：时间（since）、模型、结果、计费状态、费用（实际费用优先，否则显示估算费用）。
- 调用编号、阶段编号、模式默认隐藏，可以手动打开。Token 和供应商请求编号已经在行详情弹窗里，不变。
- 顶部汇总改成标签行：实际费用、估算费用、请求数，以及大于 0 时显示的金额未知数。

### P3 上下文检查器、检索实验室、提交与基线、故事状态回放、系统健康
- 属于诊断或运维用途，见第五节的导航调整。
- 表格中的编号列默认隐藏，时间改用 `since()`；页面说明放进「?」提示。

### P3 规划类页面：原始要求、设定与蓝图、卷与故事弧、场景规划
- 去掉“记录编号”“来源记录编号”“结构记录编号”“所属大纲记录编号”这类独立字段，改成标题后的灰色小字。
- 「版本边界」「原始输入」等区块的长说明放进「?」提示。

### P3 设置页：通用设置、模型单价
- 字段的帮助说明保持一句话；长说明（例如单价匹配规则）放进字段旁的「?」提示。

## 五、导航简化

单本小说的子导航现在有 **20 项**，分为 6 组。建议改为“常用 + 更多”：

| 分组 | 保留的页面 |
|---|---|
| 概览 | 概览 |
| 规划 | 设定与蓝图、章节大纲、场景规划 |
| 人物与世界 | 人物与实体库、角色知识与时序、伏笔账本 |
| 正文 | 章节目录、正文工作台、阅读器 |
| 交付 | 成品验收、导出中心、正式稿修订 |
| **更多（默认收起）** | 原始要求与覆盖、卷与故事弧、运行与恢复、上下文检查器、检索实验室、费用明细、提交与基线、故事状态回放 |

- “运行与恢复”平时可以从概览页的“查看运行进度”进入，所以放进“更多”。
- 能否把“更多”分组做成可收起，需要先确认 Filament v5 子导航对 `NavigationGroup::collapsible()` 的支持情况。如果不支持，就只把这几页放到最后一组。

## 六、文案收紧

- 页面和区块的 `description` 一律不超过 30 字，超出的部分放进「?」提示，做法同 Prompt 模板页标题旁的提示图标。
- 下面这类重复出现的安全提示，每个页面只保留一处：
  - “金额未知不代表免费”
  - “不调用 AI”
  - “不代表人工阅读”
- 字段标签不再出现内部概念：
  - “冻结正文记录 #”改为“正文版本”
  - “阶段编号”改为“步骤”
  - “调用日志编号”只在「请求与费用记录」区块里保留

## 七、实施顺序与测试

| 阶段 | 内容 | 预计涉及的测试 |
|---|---|---|
| 1 | 第三节全局规则 + 小说概览 + 正文工作台「运行与历史」 | B01NovelCreationTest、ChapterContentWorkbenchViewTest，以及断言“已领用 / 请求上限”等文案的用例 |
| 2 | 运行与恢复、生产总览、大纲 | 运行台、生产总览、大纲相关测试 |

- 每个阶段完成后，运行受影响的测试文件，并执行 `vendor/bin/pint --dirty --format agent`。
- 原则上只改展示，不改业务逻辑。已有测试中对“请求次数可见”的断言，改为先展开「请求与费用记录」区块再检查，或者检查区块内的内容。

## 八、需要决定的事项

1. **预算告警是否还要自动展开**：本方案建议始终收起，只用顶部标签提醒。如果你希望预算用尽时仍然直接展开，第 3.3 条保持现状。
2. **子导航“更多”分组**：放进去的页面是否合适，特别是“运行与恢复”和“费用明细”是否需要留在常用区。
3. **确认弹窗中的计费说明**：缩短后是否还要保留完整版，作为可展开段落；涉及授权的文案是否需要原样保留以满足审计要求。
